The real question: what is the limit on each stretch, and how sure are we? Then spend editor-hours only where the math says a human is needed.

P(speed | evidence) ∝
  P(speed | road morphology) ← prior: legal default (Circular 38)
 × Π P(observation | speed)   ← independent evidence: street-view signs
 × Π P(speed | neighbour seg) ← coupling: speed is spatially autocorrelated
AI detects  ·  Rules + graph reason  ·  Humans confirm — the architecture throughout (RoadTagger, He et al. 2020).

Evidence & compliance
KM 09
Two
tracks

Circular 38 keys the limit on morphology, not road class

SATELLITE

Morphology → default prior

divided/single, lane count, built-up. At launch: free basemap only (read by eye). Purchased + CV later.

STREET-VIEW

Signs → override the default

these are the change-points. At launch: the primary evidence (Mapillary → own dashcam).

Compliance line (do not blur): satellite → legal-default limit is legitimate, scalable evidence. A posted (non-default) limit still needs the sign image. Cross this line → changesets reverted + accounts banned.

Where it grows
KM 11
One editor,
many tools

The same editor becomes a multi-tool QA platform

Leadership flagged five OSM tools to fold in. The lazy-strategic move: don't embed five sites — give the editor a tool suite, like Bolt's Atlas. One map shell + one data substrate, each tool a lens. The shell is traffic/lanes today; the substrate is the planned Editor Spatial DB. New capabilities plug in as modules, reusing the worklist + evidence policy.

ModuleRuns onWhen
maxspeed · lanes · signslive OSM (Overpass)now
Turn restrictions · max-height / trucklive OSM (Overpass) — zero infraPhase 2
Change-tracking — who edited what, with evidenceEditor Spatial DB (diff feed)Phase 3
Parking + capacityEditor Spatial DB (osm2pgsql)Phase 3+
Highest-leverage tool: change-tracking. With 20–30 paid-per-km editors and evidence-per-edit mandatory, a "what changed in this corridor, by whom, with what evidence" feed is direct QA — and it's exactly what the Editor DB is for, so it justifies that backend rather than just consuming it. Bolt Atlas itself isn't integratable (private GPS) — we copy the checks, not the site.

Five decisions that belong to leadership

  • Evidence policy (sets the rollout speed ceiling). Recommended: hybrid — posted (non-default) limits need street-view; visible-morphology defaults tagged source=survey/imagery at human pace, not a bot import.
  • Imagery source & budget — internal tile server vs commercial sub-metre; how much, where. Start procurement in parallel now so it lands after launch.
  • Build vs buy CV — own model (owns evidence + retraining loop) vs vendor.
  • Write-back timing — how long to stay export-first before funding the Editor Spatial DB.
  • Editor operations — headcount, pay-per-km rate, QA gate.
