MapOps Toolkit · Introduction & how to use

MapOps Toolkit — the system for editing Vietnam map data

The MapOps Toolkit is one controlled editing layer between a local OSM extract (PBF) and the production map. It ingests many sources, fuses them into suggestions a human confirms with evidence, stages every change as versioned OSM XML / osmChange (.osc), gates it through review, then both serves it in production and can push it back to live OSM. Two editing tracks share that one pipeline: geometry & QA (Quân) and metadata (Tuệ). This page introduces the system and shows how to use it.

Metadata track: Tuệ · Geometry & QA track: Quân · Editor DB / backend: with O4 + infra

Geometry & QA node · led by Quân

Road geometry, topology & the review gate

  • Digitise / align / split ways; conflate new roads from satellite & MMS
  • Connectivity & route-relation integrity (his RouteSense C1–C7 checks)
  • Changeset review → approve gate before push (OSMCha-style diff)
  • Tool: JOSM today; clone GeoLibre for in-browser geometry editing if needed
Metadata node · led by Tuệ

Attribute (tag) editing — table-based

  • The lane-visualizer concept: one row per way, inline edit, evidence links
  • Length-weighted completeness, edit-freshness profile, Mapillary/JOSM/iD deep-links
  • Presets drive the columns: maxspeed (live) → extensible to maxheight, turn restriction, lanes
  • Every edit carries street-view evidence + provenance into the changeset

Suggestion engine — AI detects, rules & probability reason, human decides

Multi-source, never blind-copy. Each input drops observation rows (lat, lon, attr, value, source, confidence, date, image). For a given way + attribute the engine produces one ranked suggestion:

  • Decision tree — deterministic legal/morphology rules (Circular 38/2024: carriageway type → default speed). Already encoded as the editor's U/R legal defaults.
  • Bayesian fusion — combine noisy observations into a posterior P(value | evidence): a Mapillary sign, a GSV read, the legal prior, and neighbour-segment consensus each update belief, weighted by source reliability.

The human editor sees value + posterior + the evidence behind it, and accept / override / reject — recorded on the edit. No changeset ships without verifiable evidence (the SOP rule that keeps accounts un-banned).

How to use

Metadata track — edit a road's attributes

  1. Open a road. In the Editor, Search by ref / name / id (e.g. QL.51), or click Open → from the Dashboard, or deep-link /editor?ref=QL.51.
  2. Read the speed profile. Bar height = maxspeed, colour = edit freshness (green fresh → red ≥2 yr stale), grey = missing. Use the zoom slider on long routes; hover a bar for segment stats.
  3. Edit in the table. One row per way. Pick a preset (Max speed), inline-select a value or apply the U / R legal default (Circular 38). Checkbox + Shift-range to bulk-set; a blue ring marks a staged edit.
  4. Verify with evidence. Per-row chips — 📷 Mapillary, iD, JOSM, L0 — open street view / editors at that segment. No edit ships without a street-view check.
  5. Stage & apply. Copy emits way,maxspeed CSV to apply in iD/JOSM today; later it writes straight to the Editor DB.

Geometry & QA track — RouteSense

  1. Check a route. Search a relation → the C1–C7 checks flag connectivity islands, oneway / flow, maxspeed sanity, broken turn restrictions, ref continuity, lanes and access. Filter by severity, click a row to zoom + deep-link iD.
  2. Review a mapper. Changeset mode: enter an OSM username → per-changeset tag diffs, moved-node arrows, deleted geometry (OSMCha-style), and edit-km totals.
Everything stays in sync. Click a segment on the map, the table, or the speed profile and the other two focus the same way — so evidence, edit and chart always agree.
Tip. Hover any table row to highlight that segment on the map in place; the (Z) chip zooms to it. Drag the divider to resize table vs map; the layer control (top-right) switches base imagery or takes a custom {z}/{x}/{y} tile source.

Editor DB — PostGIS schema (proposed)

Temporal Spatial DB: versioned, write-heavy. feature = the editable entity; observation = the OKR [lat,lon,loại,giá trị,nguồn,ngày] row; edit = the temporal change log; changeset = the review/approve/push unit. Both tracks write the same tables.

-- Editor (Temporal) Spatial DB — PostGIS, versioned, write-heavy
CREATE EXTENSION IF NOT EXISTS postgis;

-- 1 · Canonical editable feature (forked from local PBF / live OSM)
CREATE TABLE feature (
  feature_id   bigserial PRIMARY KEY,
  osm_type     text NOT NULL CHECK (osm_type IN ('node','way','relation')),
  osm_id       bigint,                          -- null until first push to OSM
  geom         geometry(Geometry,4326) NOT NULL,
  tags         jsonb NOT NULL DEFAULT '{}',     -- current accepted tag set
  track        text CHECK (track IN ('geometry','metadata')),
  version      int  NOT NULL DEFAULT 1,
  base_version int,                             -- live-OSM version forked from (conflict check)
  status       text NOT NULL DEFAULT 'clean'
                 CHECK (status IN ('clean','draft','staged','approved','pushed','conflict')),
  updated_by   text,
  updated_at   timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX feature_geom_gix ON feature USING gist (geom);
CREATE INDEX feature_osm_idx  ON feature (osm_type, osm_id);
CREATE INDEX feature_tags_gin ON feature USING gin (tags);

-- 2 · Multi-source observations  (the OKR [lat,lon,loại,giá trị,nguồn,ngày] row)
CREATE TABLE observation (
  obs_id     bigserial PRIMARY KEY,
  geom       geometry(Point,4326) NOT NULL,
  attr       text NOT NULL,                   -- 'maxspeed'|'maxheight'|'turn'|'lanes'…
  value      text NOT NULL,
  source     text NOT NULL,                   -- 'osm'|'mapillary'|'gsv'|'satellite'|'legal_tt38'|'probe'
  confidence real,                            -- source-reported reliability 0..1
  observed_at date NOT NULL,
  image_ref  text,                            -- evidence URL (Mapillary/GSV/screenshot)
  raw        jsonb
);
CREATE INDEX observation_geom_gix ON observation USING gist (geom);
CREATE INDEX observation_attr_idx ON observation (attr);

-- 3 · Engine output: per-feature suggestion (Bayesian posterior + decision-tree rule)
CREATE TABLE suggestion (
  sug_id     bigserial PRIMARY KEY,
  feature_id bigint REFERENCES feature ON DELETE CASCADE,
  attr       text NOT NULL,
  value      text NOT NULL,
  posterior  real NOT NULL,                   -- P(value | evidence)
  method     text NOT NULL CHECK (method IN ('bayes','rule_tt38','consensus')),
  evidence   bigint[],                        -- observation ids that fed it
  rationale  jsonb,                           -- priors / rule path, shown to the editor
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX suggestion_feat_idx ON suggestion (feature_id, attr);

-- 4 · Changeset: groups edits for review → approve → push (O3KR3)
CREATE TABLE changeset (
  changeset_id     bigserial PRIMARY KEY,
  title            text,
  comment          text,
  opened_by        text NOT NULL,
  opened_at        timestamptz NOT NULL DEFAULT now(),
  status           text NOT NULL DEFAULT 'open'
                     CHECK (status IN ('open','review','approved','pushed','reverted')),
  reviewed_by      text,
  osm_changeset_id bigint,                    -- set after upload to live OSM
  closed_at        timestamptz
);

-- 5 · Temporal edit log: every staged change (geometry OR metadata) + provenance
CREATE TABLE edit (
  edit_id      bigserial PRIMARY KEY,
  feature_id   bigint REFERENCES feature ON DELETE CASCADE,
  changeset_id bigint REFERENCES changeset,
  track        text NOT NULL CHECK (track IN ('geometry','metadata')),
  op           text NOT NULL CHECK (op IN ('create','modify','delete')),
  before       jsonb,                          -- snapshot before (tags / geom)
  after        jsonb,                          -- snapshot after
  from_sug     bigint REFERENCES suggestion,   -- the suggestion accepted/overridden
  decision     text CHECK (decision IN ('accept','override','reject')),
  evidence     jsonb,                          -- street-view link(s) — mandatory per SOP
  editor_id    text NOT NULL,
  created_at   timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX edit_feat_idx ON edit (feature_id);

-- 6 · Metadata presets (drive the table editor: maxspeed, maxheight, turn, lanes)
CREATE TABLE preset (
  preset_id text PRIMARY KEY,                  -- 'maxspeed'|'maxheight'|'turn'|'lanes'
  label     text NOT NULL,
  attr_keys text[] NOT NULL,                  -- OSM tag keys this preset edits
  columns   jsonb NOT NULL,                    -- column defs + allowed values (the sheet)
  rule_ref  text                              -- e.g. 'circular_38_2024' decision tree
);
